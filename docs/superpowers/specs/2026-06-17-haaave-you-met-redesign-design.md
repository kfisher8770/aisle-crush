# "Haaave you met…?" — Wedding Wingman App Redesign

**Date:** 2026-06-17
**Status:** Approved, implementing
**Supersedes:** the original "Aisle Crush" swipe/match MVP

## One-liner

A mobile-only party web app for Katherine & Antoine's wedding (June 20). Wingmen
build dating-style profiles for their single friends, then compete on a
leaderboard by collecting emoji reactions, matches, and — the heart of it —
logging real-life wedding antics (with photo proof) onto their single's profile.
Named after Barney Stinson's wingman catchphrase from *How I Met Your Mother*.

## Goals

- Make the **wingman** the star: create/manage one or more single profiles, log
  real-world events, climb the leaderboard.
- Make **browsing fun, not Tinder**: anyone (not just singles) flips through
  profiles and reacts with playful emoji. It must read as a game, not a real
  matchmaking app.
- Give **singles** a light role: same browse surface, plus a high-value 💍 Match
  button and the ability to make their own profile.
- **Mobile-only.** The wedding phone is the sole surface. Thumb-friendly, big tap
  targets, no hover dependence.

## Non-goals

- No accounts/passwords. Lightweight name-based identity only.
- No real-time/websockets. Pull-on-load + refresh is fine for a one-day event.
- No moderation queue. Trust-based; admin can reset/delete.
- No desktop layout work beyond "it doesn't break."

## Personas & flows

### 1. Wingman (primary)
- Enters their name on the **Me** tab. Sees assigned single(s) from `assignments`
  plus any profile they've created.
- **Create a profile** for a single friend (multi-step form: basics, hype, flags,
  optional photo, secret).
- **Manage** existing profiles: edit, delete, and **log events**.
- Earns all points generated by profiles they created. Ranked on the leaderboard.

### 2. Browser / public (anyone)
- No identity needed. A random `guestId` is generated and stored in
  `localStorage` on first visit (used to dedupe reactions).
- Lands on **Browse** (swipe deck). Swiping ←/→ just flips between profiles — it
  is **not** a vote. Reacting is explicit: tap an emoji on the reaction bar.
- Emoji set (playful, intentionally not romantic): 😂 🔥 🍑 🍆 💀 😍 👏 🥂.
- Each reaction adds **+1** to the profile's creator. One of each emoji per guest
  per profile (dedup), so you can stack different emojis but not spam one.

### 3. Single (lightest)
- Identifies by name on the **Me** tab. Same Browse surface, but gets an extra
  **💍 Match** button on each profile worth **+10** to that creator (singles only,
  once per profile). Matching reveals the profile's hidden "secret" + a fun dare.
- Can create/edit **their own** profile (self-made: they are their own wingman and
  earn their own points).

## Core mechanic: points (fully balanced across sources)

Points are **computed on the fly** from reactions + matches + events — no stored
running totals, single source of truth. The leaderboard aggregates per creator.

| Source | Points | Notes |
|---|---|---|
| Emoji reaction | +1 | per guest, per emoji, per profile (deduped) |
| 💍 Match (singles only) | +10 | once per single per profile |
| **Romantic ladder** event | escalating | see below |
| **Drink-o-meter** advance | +2 | up to 3 advances |
| **Deed / chaos** event | flat | see below |
| **Custom** event | +5 | freeform text, photo still required |

**Romantic ladder** (escalating, photo proof each):
👀 Eye contact +2 · 🤝 Firm handshake +4 · 🫂 Hug +6 · 💃 Danced together +8 ·
😘 Cheek kiss +12 · 💋 The real deal +18 · 📱 Got the number +25

**Drink-o-meter** (escalating tracked status per profile, shown inline):
🍺 Tipsy → 🥴 Someone hide their keys → 🆘 We've lost them. Each advance +2.

**Deeds & chaos** (flat, photo proof each):
💐 Caught the bouquet +10 · 🎤 Nailed a speech +8 · 🕺 Owned the dance floor +8 ·
😭 Cried at the ceremony +5 · 🪱 Attempted the worm +5 · 🤵 Aggressively
"networking" with the parents +5 · 👯 Started a conga line +5

Every logged event appears on the single's public profile timeline with its photo,
label, and points — for everyone to see.

**Anti-cheat:** reactions deduped per `guestId`+emoji+profile; matches deduped per
single+profile; the **server owns the points catalog** and assigns points by event
type (client-submitted point values are ignored; custom = fixed +5).

## Architecture

Keep the existing stack — perfect for a one-day, zero-build party app:

- **Backend:** single Express server (`server.js`), flat-file `data.json` store.
- **Uploads:** add **`multer`**; event/profile photos saved to `public/uploads/`,
  URLs stored in `data.json`. (Base64-in-JSON rejected: bloats and slows the file.)
- **Frontend:** vanilla JS mobile web app. Split the current single file into
  `public/index.html`, `public/app.js`, `public/styles.css` for maintainability.
- **Admin:** `public/admin.html` updated to manage assignments, view all data &
  events, and reset.

### Navigation
Persistent bottom tab bar on every main screen: **🃏 Browse · 🏆 Leaderboard · 👤 Me**.

### Data model (`data.json`)
```jsonc
{
  "assignments": [ { "wingman": "Sophie", "single": "Lucas" } ],
  "profiles": [
    {
      "id": 1718600000000,
      "singleName": "Lucas",
      "createdBy": "Sophie",          // creator/wingman name; === singleName if self-made
      "selfMade": false,
      "age": 28,
      "photoUrl": "/uploads/abc.jpg", // optional
      "vibes": ["🎸 Music lover"],
      "pitch": "…", "habit": "…", "cry": "😭 Absolutely",
      "dance": 4, "greenFlag": "…", "redFlag": "…",
      "secret": "…",                  // hidden until a single matches
      "drinkLevel": 1,                // 0..3 → drink-o-meter status
      "reactions": [ { "guestId": "g_x", "emoji": "😂", "at": "ISO" } ],
      "matches":   [ { "by": "single:lucas", "at": "ISO" } ],
      "events": [
        { "id": "...", "type": "ladder|drink|deed|custom", "emoji": "💋",
          "label": "The real deal", "points": 18, "photoUrl": "/uploads/x.jpg",
          "at": "ISO" }
      ],
      "createdAt": "ISO"
    }
  ]
}
```
`matches`/`swipes` from the old schema are migrated/replaced; a tiny migration on
read backfills missing fields (`reactions`, `matches`, `events`, `drinkLevel`,
`createdBy`) so existing data doesn't crash the server.

### API surface
- `GET  /api/event-catalog` — server-owned list of event types + points (client renders chips).
- `GET  /api/profiles` — all profiles, with computed `points` + reaction tallies; `secret` omitted unless `?revealFor=<single>` matched.
- `POST /api/profiles` — multipart (photo + fields) → create.
- `PUT  /api/profiles/:id` — multipart → edit (creator, name-checked).
- `DELETE /api/profiles/:id` — delete (creator, name-checked).
- `POST /api/profiles/:id/react` — `{ guestId, emoji }` → toggle reaction (+1/-1).
- `POST /api/profiles/:id/match` — `{ single }` → record match (+10, deduped).
- `POST /api/profiles/:id/events` — multipart (photo + `{ type }`, label/custom text) → log event; server assigns points.
- `GET  /api/leaderboard` — creators ranked by total computed points (across their profiles).
- `GET  /api/assignments`, `POST /api/admin/assignments`, `POST /api/admin/reset`, `GET /api/admin/data`.

### Points engine (testable unit)
A pure `computePoints(profile)` / `leaderboard(data)` module is the one piece with
real logic — covered by unit tests (reaction dedupe, match value, event catalog
totals, leaderboard aggregation/sorting). UI verified by running the app in a
browser.

## Branding & feel
- Name **"Haaave you met…?"** with a Barney/HIMYM meme or gif on the landing/Me
  screen to land the joke. (Use a static asset in `public/`; no hotlinking.)
- Keep the warm pink palette but tighten spacing/hierarchy for small screens.
- Copy is cheeky throughout (reaction labels, event names, empty states).

## Testing & verification
- Backend: unit tests for the points engine + a couple of route smoke tests.
- Frontend: launch the server, drive it in a real mobile-viewport browser
  (Playwright) — create a profile, react, log an event with a photo, match as a
  single, check the leaderboard updates.

## Out of scope for v1 (parked)
Reaction "full house" combo bonus, crowd-award finale voting, profile comments/
roasts, first-mover streaks. Easy to add later; not in this build.
